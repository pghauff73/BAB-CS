# Qualification Summary Evidence

`qualification-summary.json` is generated by the release-qualification workflow
and is a required, checksummed manifest artifact. It replaces manually copied
surface counts with values derived from canonical repository owners.

Generate a development summary with a prepared evidence directory:

```bash
PYTHONPATH=src python tools/release_evidence.py write-qualification-summary \
  --repository-root . \
  --evidence-dir artifacts/release \
  --benchmark-manifest benchmarks/manifest.json \
  --ci-workflow .github/workflows/ci.yml \
  --latest-public-release v1.0.0 \
  --output artifacts/release/qualification-summary.json
```

The release workflow does not use `--allow-dirty`. A tracked dirty tree fails
closed.

## Canonical Owners

| Summary field | Canonical owner |
| --- | --- |
| Source commit and dirty state | Git `HEAD`, tracked index, and tracked worktree |
| Project, package, licence, requirement, wheel | `src/babcs/_project.py` |
| Test methods and modules | Python syntax in `tests/test_*.py` |
| Bounded candidate methods | `src/babcs/candidates.py` |
| Benchmark cases and configurations | `benchmarks/manifest.json` |
| CI Python versions | `.github/workflows/ci.yml` |
| Workflow run identity | release evidence environment files |
| Latest public release | GitHub Releases API at qualification time |

The release manifest validates that the summary names the same source commit,
candidate tag, creation time, workflow identity, package version, and wheel, and
that it does not claim a dirty source tree is clean. The artifact does not
represent human release approval.
